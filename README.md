# JevOnly

**A harness that lets Jev do any task through closed votes -- the code builds the options, Jev only picks.**

JevOnly is a set of rules for driving a task with nothing but closed-choice judgments from
[Jev](https://typesafe.ai): no planner model, no helper LLM, no free text. Code constructs every
available option -- from the environment's state, the goal and an explicit fact register -- and Jev
assigns probabilities and picks. Then the code verifies the effect, undoes what did not work, and
keeps a register of values read off the environment. That makes a run inspectable down to every
rejected alternative, keeps each call small enough for a System One model, and makes invented values
impossible: anything typed came from the goal, a caller-supplied fact, or text copied from the
environment.

The rules live in `jevonly.core` and are environment-agnostic. The first environment is a real
Chromium browser (`jevonly.envs.browser`), which is what the quickstart and the live viewer below use;
see [Writing an environment](docs/architecture.md#writing-an-environment) to drive something else
with the same loop.

## Run it in 60 seconds

### Prerequisites

| Requirement      |              Version | Check                                         |
| ---------------- | -------------------: | --------------------------------------------- |
| Python           |                3.12+ | `python3 --version`                           |
| Node.js          |                  22+ | `node --version`                              |
| npm              | bundled with Node.js | `npm --version`                               |
| TypeSafe API key |   starts with `tsk_` | Get one at [typesafe.ai](https://typesafe.ai) |

From a clone of this repository:

```bash
./run.sh
```

The launcher creates `.venv`, installs JevOnly and its pinned Playwright dependency, installs Chromium, and starts the viewer. Open [http://127.0.0.1:7791](http://127.0.0.1:7791), paste your TypeSafe API key, enter a public start URL, and type a concrete goal such as:

> On Wikipedia's list of tallest buildings, compare the two tallest entries and report both heights.

Press **Run**. The middle pane shows Chromium live; the timeline shows every page observation, Jev vote, action, verification, copy, and undo.

You can also run without the viewer:

```bash
export TYPESAFE_API_KEY=tsk_your_key_here
jevonly run \
  --start https://en.wikipedia.org/wiki/List_of_tallest_buildings \
  --goal "Compare the two tallest entries and report both heights." \
  --variant noaccept_kb \
  --out events.jsonl
```

## Worked example

A recorded Wikipedia tallest-building comparison took **11 steps**, made **43 Jev calls**, used about **340k input tokens**, cost approximately **$0.014**, and ran for **17 seconds**. The compact log uses the same format as **Copy all logs** in the viewer; this excerpt keeps only the supplied measurements and redacts run-specific page values and probabilities:

```text
goal: [Wikipedia tallest-building comparison]
start: https://en.wikipedia.org/wiki/List_of_tallest_buildings
completion check: [run setting]
variant: [variant] · max steps: [limit] · time budget: [limit]s

+0.0s START variant=[variant] code_check=[true|false] max_steps=[limit] viewport_only=[true|false] thresholds {...}

+...s ── STEP 1 ── https://en.wikipedia.org/wiki/List_of_tallest_buildings
+...s   observe elements=[count]
+...s   done=n/a offpath=[score]
+...s   next  [probability] [candidate] | [probability] [candidate]
...
+17.0s END success=[true|false] stopped=[reason] steps=11 jev_calls=43 tokens=340,000 undos=[count] seconds=17.0
+17.0s closed calls=43 tokens=340000 cost_est=$0.014
```

The omitted rows contain the copy-selection rounds and their probabilities. Downloading `.jsonl` preserves the full page states and event payloads; the compact log deliberately omits page text.

## How it works

1. **Observe:** Playwright produces an accessibility-oriented snapshot of enabled controls, visible text, headings, values, and context.
2. **Build choices:** code turns controls into actions and adds bounded pseudo-actions for scroll, find, and copy.
3. **Vote:** one Jev request can answer “done?”, “off path?”, and “which action next?” over the same state.
4. **Bind values:** fields can receive only explicit facts, deterministic spans cut from the goal, or values copied from the page.
5. **Type without generation:** code spells a selected goal value; Jev chooses only next word, rest, stop, or a bounded keyboard key.
6. **Act and verify:** Chromium performs the selected action, then Jev compares before and after states against the action's intended effect.
7. **Recover:** reversible failures are undone and the next-best action is tried; walls, cycles, stalls, and repeated failures are withdrawn or stopped.
8. **Protect commits:** potentially irreversible actions get a separate risk vote and are never repeated unless the visible state proves the request did not land.

See [How it works](docs/how-it-works.md), [Architecture](docs/architecture.md), and the exhaustive [Event reference](docs/events.md).

## Safety and privacy

| Guard                    | Behavior                                                                                                                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Loopback viewer          | The HTTP server binds only to `127.0.0.1`.                                                                                                                                                        |
| Irreversible-action gate | A `risk >= 0.50` vote marks an action irreversible. Nothing irreversible runs on a default: the CLI skips it unless `--irreversible ask                                                           | allow`, the viewer pauses and asks you (or the policy you chose). An unconfirmed irreversible action is never replayed. |
| Credential handling      | The library reads `TYPESAFE_API_KEY` at call time. The viewer keeps a pasted key in tab `sessionStorage` and the local process for the run; it is not included in browser-child output or events. |
| Local images             | Screenshots, screencast frames, replay, and GIF generation remain in the local viewer.                                                                                                            |
| Remote judgment data     | The goal, facts, page observations, questions, and candidate descriptions are sent to TypeSafe System One. Point it at pages whose content you are willing to send there.                         |

## Current limits

| Limit                     | Consequence                                                                                                                |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| English-centric splitting | Goal spans, clauses, and copy patterns are tuned for English capitalization, dates, units, and punctuation.                |
| Automation defenses       | Sites can challenge or block Playwright; JevOnly treats pages with nothing actionable as walls rather than bypassing them. |
| One run at a time         | The viewer returns `409` if another run is active.                                                                         |
| Viewport-only observation | When enabled, off-screen controls and text are invisible until a scroll or find action reaches them.                       |
| Closed vocabulary         | JevOnly cannot compose arbitrary free text. Values must already exist in the goal, facts, or page.                         |
| Probabilistic completion  | Without a code-owned completion check, stopping is Jev's judgment rather than a verified postcondition.                    |
